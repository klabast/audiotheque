# Security Policy

## Reporting a Vulnerability

**Please do not file public GitHub issues for security vulnerabilities.**

Open a private
[security advisory](https://github.com/klabast/audiotheque/security/advisories/new)
on this repository instead. The advisory channel is private between you and
the maintainers and supports follow-up discussion, file attachments, and a
draft fix workflow.

Include:

- A clear description of the issue and the impact.
- Steps to reproduce (PoC welcome).
- The affected version (commit SHA or release tag).
- Your name / handle if you'd like to be credited.

You'll get an acknowledgement within **3 business days**. Expect a fix or
mitigation timeline within **14 days** for high-severity issues; lower-severity
findings track the next release.

## Supported Versions

Audiotheque is pre-1.0 and follows a rolling-release model — only `main` and
the most recent tagged release receive security fixes. If you're running an
older build, the fix will be: upgrade.

## Disclosure

Once a fix is shipped, the original report and the patch will be referenced
from the release notes and a GitHub Security Advisory. Reporters who want
public credit are listed there; reporters who prefer to stay anonymous are
honoured.
