# CONTRIBUTING to Audiotheque

Thank you for your interest in contributing to Audiotheque! This document outlines the contribution guidelines and expectations for this project.

## Project Philosophy

Audiotheque is a personal hobby project that I've decided to open source for the benefit of fellow music enthusiasts. It's built primarily to solve my specific needs as a music collector and self-hosting enthusiast. This has a few important implications:

1. **Personal Vision**: The project direction is guided by my personal goals and use cases.
2. **Focused Scope**: Features are added based on their value to the core mission, not popularity.
3. **Independent Development**: Development happens on my schedule and priorities.

## Ways to Contribute

Despite being a personal project, I welcome contributions in several forms:

- **Bug reports**: If something isn't working as expected
- **Code improvements**: Optimizations, fixes, or enhancements to existing features
- **Documentation**: Improvements to help others understand and use Audiotheque
- **Feature implementations**: Especially if they align with the project roadmap
- **Constructive feedback**: Thoughtful critiques that help improve the project

## Guidelines for Contributors

### Before Contributing

1. **Understand the project scope**: Read the README thoroughly to ensure your contribution aligns with the project's goals.
2. **Check existing issues**: See if your bug or feature has already been reported or discussed.
3. **For major features**: Open an issue first to discuss the approach before investing significant time.

### Code Contributions

1. Fork the repository and create a feature branch
2. Write clean, documented code that follows the project's style
3. Include tests where appropriate
4. Submit a Pull Request with a clear description of the changes and their purpose
5. Be open to feedback and revision requests

### Bug Reports

When submitting bug reports, please include:

- A clear, descriptive title
- Steps to reproduce the issue
- Expected vs. actual behavior
- Version information (OS, browser, Audiotheque version)
- Any relevant logs or screenshots

## Communication Expectations

As a personal project, I have a few expectations for communication:

1. **Be respectful and patient**: I work on this in my free time.
2. **No demands or entitlement**: Feature requests are welcome, but understand they may not be implemented.
3. **Self-reliance encouraged**: I may not be able to help with every setup issue or customization.
4. **Constructive tone**: Critique is welcome, but hostility is not.

## Implementation Preferences

- **Apple and Linux focused**: Windows support is not a priority
- **Simplicity over features**: I prefer elegant solutions over feature bloat
- **Performance matters**: Contributions should maintain or improve performance
- **Self-hosting first**: Solutions should work well in personal server setups

## What This Project Is Not

To set expectations clearly:

- This is not a democratic project where features are added based on popularity
- This is not a support-guaranteed product
- This is not trying to be a replacement for every music player out there
- This is not a project where the roadmap is determined by external requests

If you want any of the above, you are welcome to fork this project and run your own. It's AGPL v3, so the only catch is that if you run a modified version as a network service, you have to share your changes back under the same license — which is the whole point.

## License and Attribution

- All contributions will be under the project's license
- Significant contributions will be acknowledged in the project documentation

## Final Note

I appreciate your interest in Audiotheque and welcome your contributions that align with the project's vision. While I can't guarantee that every contribution will be accepted, I do promise to consider each one thoughtfully.

Remember that open source is about collaboration, but also about respecting the project maintainer's vision and boundaries. Let's work together to make Audiotheque better while keeping the process enjoyable for everyone involved.
